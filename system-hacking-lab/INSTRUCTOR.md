# 강사용 진행안과 해설

이 문서는 `basic_system.pdf` 39~49쪽을 기준으로 한 60분 수업안이다. 학생에게 배포할 명령과 활동지는 `README.md`에 있다.

## 수업 전 점검

수업 PC 한 대에서 다음을 미리 실행한다.

```bash
docker compose build
docker compose run --rm lab make check
docker compose run --rm lab pwndbg -x gdb/func1-entry.gdb ./argument
```

마지막 명령이 `func1` 시작점에서 멈추고 `RDI=1`, `RSI=2`, `RDX=3`, `RCX=4`, `R8=5`, `R9=6`을 보이면 준비가 끝난 것이다.

## 판서용 스택 변화

주소는 아래로 갈수록 작아지고 스택은 낮은 주소 방향으로 자란다고 그린다.

`main`의 프롤로그 직후:

```text
높은 주소
[RBP+8]  _start 계열로 돌아갈 복귀 주소
[RBP]    이전 RBP                 <- RBP
[RBP-8]  정렬용 8바이트 공간       <- RSP
낮은 주소
```

`push 0x7` 직후:

```text
[RBP+8]  main의 복귀 주소
[RBP]    이전 RBP                 <- RBP
[RBP-8]  정렬용 공간
[RBP-16] 7                        <- RSP
```

`call func1`이 실행된 직후, 아직 `func1` 프롤로그 전:

```text
[RSP+8]  7
[RSP]    main의 call 다음 명령 주소 <- RSP
```

`func1`에서 `push rbp; mov rbp,rsp`까지 실행한 뒤:

```text
[RBP+16] 7번째 인자
[RBP+8]  main으로 돌아갈 복귀 주소
[RBP]    main의 RBP               <- RBP, RSP
```

따라서 “7번째 인자는 항상 `RSP+8`”이라고 외우게 하면 안 된다. `RSP`는 프롤로그와 지역 변수 할당 때마다 움직인다. 프레임 포인터를 쓰는 현재 빌드에서는 프롤로그 뒤 7번째 인자가 `RBP+16`에 있다는 관계가 안정적이다.

## 시연 중 강조할 점

- `push`는 x86-64에서 `RSP`를 8 줄이고 값을 저장한다.
- `call`은 대상 함수로 점프하기 전에 다음 명령 주소를 스택에 넣는다.
- `ret`은 스택 최상단 값을 꺼내 `RIP`로 사용한다.
- `leave`는 현재 예제에서 `mov rsp,rbp; pop rbp`와 같은 역할을 한다.
- `func1` 반환 후 `add rsp,0x10`은 스택의 7번째 인자 8바이트와 정렬 공간 8바이트를 호출자 `main`이 함께 회수하는 동작이다.
- `mov edi,1`처럼 32비트 하위 레지스터에 쓰면 해당 64비트 레지스터의 상위 32비트는 0으로 채워진다.
- `endbr64`는 Intel CET의 간접 분기 보호 명령이며, 스택 프레임을 만드는 프롤로그 명령은 아니다.
- `break *func1`처럼 정확한 함수 첫 명령에서 멈추면 GDB의 소스 인자 표시는 프롤로그 전 위치 정보를 아직 해석하지 못해 0으로 보일 수 있다. 이때는 `RDI`부터 `R9`까지의 실제 레지스터 값을 기준으로 설명한다.

## 교재 표현에 덧붙일 정확한 설명

“x64부터 fastcall로 통일”이라는 표현은 모든 운영체제에 동일한 하나의 규약이 있다는 뜻으로 받아들이면 부정확하다. 이 Docker는 Linux의 **System V AMD64 ABI**를 사용한다. 정수 인자 1~6은 `RDI, RSI, RDX, RCX, R8, R9` 순서다. Windows x64 규약은 첫 네 정수 인자에 `RCX, RDX, R8, R9`를 쓰고 shadow space도 요구한다. 이 수업에서는 Linux 규약만 관찰한다고 범위를 분명히 한다.

또한 C 소스의 인자 평가 순서와 ABI에 따라 최종 인자값을 배치하는 위치·명령 순서는 서로 다른 개념이다. 이 예제에서는 상수라서 부작용이나 평가 순서 문제가 드러나지 않는다.

## 활동지 정답

정확한 주소값은 실행마다 달라질 수 있으므로 값 자체보다 상대 변화로 채점한다.

| 관찰 시점 | `RSP` 변화 | `RBP` 변화 | 스택 최상단 값 | 핵심 설명 |
|---|---|---|---|---|
| `main` 진입 | 기준 | 아직 호출자 값 | `main`의 복귀 주소 | `call main` 계열이 저장 |
| `push rbp` 직후 | `-8` | 아직 이전 값 | 이전 `RBP` | 호출자 프레임 포인터 보존 |
| `push 0x7` 직후 | 추가로 `-8` | `main` 프레임 기준 유지 | `7` | 7번째 인자는 스택 전달 |
| `call func1` 직후 | 추가로 `-8` | `main` 값 유지 | `main` 복귀 주소 | `call`의 부수 효과 |
| `func1`의 `mov rbp,rsp` 직후 | 직전 `push rbp`로 `-8` | 현재 `RSP`로 변경 | `main`의 `RBP` | 새 스택 프레임 완성 |
| `leave` 직후 | 저장된 `RBP` 위까지 복원 | `main`의 `RBP`로 복원 | `main` 복귀 주소 | 지역 프레임 제거 |
| `ret` 직후 | `+8` | 복원값 유지 | 호출자 쪽 다음 값 | 복귀 주소가 `RIP`로 이동 |

확인 질문 정답:

1. `EDI` 쓰기는 `RDI`의 상위 32비트를 0으로 만든다.
2. System V AMD64 ABI의 호출 경계 정렬을 맞추기 위해서다. 이 예제에서는 정렬 공간 8바이트와 스택 인자 8바이트를 함께 사용해 `call` 직전 `RSP`를 16바이트 경계에 둔다.
3. `call`이 복귀 주소를 push하고, 피호출자의 프롤로그도 이전 `RBP`를 push한 뒤 지역 공간을 할당할 수 있기 때문이다.
4. `add rsp,0x10`으로 정렬 공간과 7번째 인자를 함께 회수한다.
5. `mov rsp,rbp` 다음 `pop rbp`와 같은 효과다.

## 평가 기준 예시

- 3점: 여섯 레지스터의 순서를 정확히 말한다.
- 2점: `call`과 `ret`의 스택 효과를 연결해 설명한다.
- 2점: 7번째 인자의 위치를 함수 진입 전과 프롤로그 후 각각 찾는다.
- 2점: 프롤로그와 에필로그에서 `RSP`, `RBP` 변화를 설명한다.
- 1점: 호출자 정리인 `add rsp,0x10`을 찾는다.
